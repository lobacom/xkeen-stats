# XKeen Stats

Лёгкая самостоятельная страница статистики Xray для роутеров Keenetic с Entware.
Для сбора статистики и входа используются только Xray и сам сервис.
XKeen UI не требуется.

## Возможности

- Пользователи VLESS, открытые подключения и IP-адреса.
- Полученный и отправленный трафик, текущая скорость, последняя активность.
- Итоги за сегодня, месяц и всё время; последние 400 дней истории.
- Статистика входящих каналов и выходов Xray.
- Пояснения назначения домашних TCP/UDP-каналов, VPN-входов и выходов в интернет.
- Поиск, сортировка, фильтр онлайн-пользователей и выгрузка CSV.
- Собственный пароль, сессии с ограниченным сроком и выход из аккаунта.
- Проверка новых версий и установка подписанных обновлений со страницы.

Опрос выполняется каждые 5 секунд без сброса счётчиков. Состояние сохраняется
раз в минуту и при штатной остановке. Дневные и месячные периоды используют
московское время. График скорости показывает последние пять минут открытой страницы.

Одинаковые `email` в разных входящих подключениях объединяются в одного пользователя.
Онлайн означает наличие открытого подключения Xray; число IP не равно числу устройств.
Трафик прозрачного прокси без VLESS учитывается суммарно по входящим каналам.
Во вкладках каналов колонка «Назначение» строится по `protocol`, настройкам
перехвата и транспорту из конфигурации Xray. Имена тегов не определяют тип или страну:
например, VLESS-вход с любым тегом будет описан как VLESS, а `freedom` — как прямой
выход (либо как цепочка, если настроен другой выход для подключения).
Входной канал не определяет конечный выход: его выбирают правила маршрутизации.
Статистика пользователей, входов и выходов отражает разные этапы одного трафика;
их суммы нельзя складывать. Пояснения участвуют в поиске и выгружаются в CSV.

История до включения статистики не восстанавливается. При аварийном завершении
Xray могут потеряться последние 5 секунд между опросами, при отключении питания —
последняя несохранённая минута.

## Требования

- Linux с `/proc`, Entware и Xray.
- Xray с методами StatsService `QueryStats` и `GetUsersStats`; проверено с 26.11.9.
- Собственный пароль: создаётся в браузере при первой установке или через CLI.
- Для сборки — Go 1.27 или новее. Используется только стандартная библиотека.

В текущей версии адреса интерфейса и разрешённая подсеть рассчитаны на типовую
сеть `192.168.1.0/24` с роутером `192.168.1.1`. При другой схеме сети нужно
согласованно изменить проверку подсети в `main.go`, ссылки в `index.html`,
адрес запуска и правила LAN-фильтра. Универсального установщика пока нет.

## Сборка

Проверки:

```sh
go test ./...
go vet ./...
```

Для MIPS little-endian с программной плавающей точкой:

```sh
GOOS=linux GOARCH=mipsle GOMIPS=softfloat CGO_ENABLED=0 \
  go build -trimpath -ldflags="-s -w -X main.version=$(cat VERSION)" -o dist/xkeen-stats .
```

Другие архитектуры требуют подходящего `GOARCH`. Рекомендуется собирать бинарник
самостоятельно; готовые бинарники и данные конкретного развёртывания не входят
в исходный репозиторий.

## Настройка Xray

Пример дополнений к существующему конфигу; это не полный конфиг для замены:

```json
{
  "stats": {},
  "api": {
    "tag": "xkeen-stats-api",
    "listen": "127.0.0.1:10085",
    "services": ["StatsService"]
  },
  "policy": {
    "levels": {
      "0": {
        "statsUserUplink": true,
        "statsUserDownlink": true,
        "statsUserOnline": true
      }
    },
    "system": {
      "statsInboundUplink": true,
      "statsInboundDownlink": true,
      "statsOutboundUplink": true,
      "statsOutboundDownlink": true
    }
  }
}
```

Включите пользовательские счётчики для фактических уровней клиентов. Каждому
учитываемому пользователю нужен непустой уникальный `email` в настройках входящего
подключения. Добавления должны сохранять существующие `policy` и остальные поля.
Конфигурацию необходимо проверить средствами Xray перед применением.

Если XHTTP завершается за локальным Nginx, для реальных IP необходимо согласовать
передачу `X-Forwarded-For` и `sockopt.trustedXForwardedFor` согласно документации
вашей версии Xray. Прокси должен перезаписывать клиентский заголовок фактическим
адресом, а сам Xray-вход должен быть недоступен в обход доверенного прокси.
В проверенной версии `trustedXForwardedFor` перечисляет имена заголовков-маркеров.

Штатный [StatsService](https://xtls.github.io/en/config/api.html) читает счётчики;
Access Log для работы этого компонента не требуется.

## Запуск

Параметры по умолчанию:

```text
-listen 192.168.1.1:1001
-config /opt/etc/xray/configs/00_cascade.json
-auth /opt/etc/xkeen-stats/auth.json
-setup-token /opt/etc/xkeen-stats/setup-token
-state /opt/var/lib/xkeen-stats/state.json
-api 127.0.0.1:10085
```

Файлы `S99xkeen-stats` и `051-xkeen-stats-lan.sh` — примеры автозапуска
и netfilter-hook для этой схемы сети. Перед установкой проверьте соответствие
адреса, подсети, интерфейса и путей вашему роутеру. Для существующей установки
сохраните путь её текущего состояния статистики: другой `-state` начнёт отдельную историю.

Бинарник размещается в `/opt/sbin/xkeen-stats`, init-скрипт — в `/opt/etc/init.d/`,
LAN-hook — в `/opt/etc/ndm/netfilter.d/`. Скрипты должны быть исполняемыми.
Страница открывается по адресу `http://192.168.1.1:1001/`.
В штатной консоли NDMS команды запускают через `exec`:

```text
exec /opt/etc/init.d/S99xkeen-stats status
exec /opt/etc/init.d/S99xkeen-stats restart
exec /opt/etc/init.d/S99xkeen-stats stop
```

Остановка сборщика не останавливает Xray.

## Настройка пароля

Пароля по умолчанию нет. При первой установке владелец создаёт его в браузере;
пароли роутера и других панелей автоматически не используются.

### Первый запуск: создание в браузере

1. Запустите сервис обновлённым init-скриптом. Если пароль ещё не задан, в консоли
   появится одноразовая ссылка первоначальной настройки.
2. Откройте её в домашней сети. На странице «Создать пароль» введите пароль дважды.
3. Нажмите «Создать пароль». После сохранения откроется статистика; ссылка настройки
   перестанет действовать. При следующих посещениях будет обычная форма «Вход».

Если ссылка потерялась, её можно повторно вывести в SSH-консоли администратора:

```text
exec /opt/sbin/xkeen-stats -setup-link
```

Ссылка содержит случайный одноразовый код. Он не выдаётся анонимным посетителям,
хранится на роутере в закрытом файле `setup-token` (0600) и удаляется после настройки.
Без ссылки или её кода нельзя задать первый пароль, даже находясь в LAN. Код передаётся
во фрагменте URL, не попадает в HTTP-путь и удаляется из адресной строки страницей.
Существующий пароль через этот мастер заменить нельзя. Повреждённый файл авторизации
не считается новой установкой и не открывает мастер.

При установке этой функции нужны актуальные init-скрипт и LAN-hook: первый
вызывает `-prepare-auth`, второй проверяет `-check-access`. На уже настроенной
инсталляции обе команды принимают существующий пароль и ничего не сбрасывают.

### Настройка или сброс через CLI

При необходимости задайте или сбросьте пароль через SSH, передав одну строку на stdin
процесса `xkeen-stats -set-password`. Пароль должен занимать от 8 до 1024 байт.
Пример для интерактивного shell Entware:

```sh
/opt/etc/init.d/S99xkeen-stats stop
(
  trap 'stty echo' EXIT HUP INT TERM
  stty -echo
  printf 'Пароль: ' >&2
  IFS= read -r stats_password
  stty echo
  printf '\n' >&2
  printf '%s\n' "$stats_password" | /opt/sbin/xkeen-stats -set-password
)
/opt/etc/init.d/S99xkeen-stats start
```

Пароль не передаётся аргументом процесса и не записывается в историю shell.
Пример выполняется в shell Entware, а не непосредственно в консоли NDMS.
Если файл авторизации находится в другом месте, добавьте `-auth /путь/auth.json`.
Команда `xkeen-stats -check-auth` проверяет настроенный пароль без запуска сервера;
`-check-access` также допускает защищённую одноразовым кодом первоначальную настройку.

Изменение пароля выполняется той же командой при остановленном сервисе и отзывает
все его сессии. Сессии других приложений не затрагиваются. При обновлении с версии,
использовавшей стороннюю панель, сначала создайте собственный пароль; старые cookies
не принимаются. Сохраняйте прежний `-state`, чтобы продолжить накопленную историю.

## Данные и доступ

API проверяет адрес клиента, Host и собственную cookie `xkeen_stats_session`.
Пароль хранится как PBKDF2-HMAC-SHA256 с 600 000 итераций и случайной солью 16 байт.
Используется [реализация стандартной библиотеки Go](https://pkg.go.dev/crypto/pbkdf2);
число итераций соответствует [рекомендации OWASP для PBKDF2-HMAC-SHA256](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2).
Открытый пароль не сохраняется. Файл авторизации содержит только хеш, соль и SHA256
хеши токенов сессий, записывается атомарно с правами 0600; каталог создаётся с 0700.

Токен сессии содержит 32 случайных байта. Срок сессии — 12 часов, до 32 одновременных
сессий; они сохраняются при перезапуске сервиса. Cookie имеет HttpOnly, SameSite=Strict
и Secure при HTTPS. Выход отзывает соответствующую сессию на сервере. Вход и выход
проверяют Origin. После пяти неудачных входов за минуту запросы с этого IP временно
ограничиваются; одновременно выполняется только одна проверка пароля, чтобы
сдерживать нагрузку на роутер. При повреждённом файле авторизации веб-сервер не
запускается. На новой установке без файла доступен только защищённый мастер создания
пароля; статистика и обновления требуют входа. Удаление файла у уже работающего
настроенного сервиса закрывает доступ и не включает мастер повторно.

На маломощных MIPS-устройствах проверка пароля может занимать несколько десятков
секунд (на проверенном роутере — около 23 секунд). Это происходит только при входе;
дальнейшие запросы используют сессию и не вычисляют парольный хеш повторно.

Порт статистики предназначен для доверенной LAN, StatsService — только для loopback.
HTTP не шифрует пароль и сессию при передаче по LAN. Не публикуйте порты напрямую
в Интернет. Настоящие конфиги Xray, состояния статистики, cookies, журналы,
скриншоты с пользователями и локальные скрипты доступа в Git не добавляются.
Папка `.local/` и типичные файлы реквизитов исключены через `.gitignore`.

## Собственные подписи каналов

Необязательный `labels.json` рядом с файлом `auth.json` позволяет уточнить
назначение конкретных каналов. По умолчанию это `/opt/etc/xkeen-stats/labels.json`:

```json
{
  "inbound:office-vpn": {
    "title": "VPN для офиса",
    "description": "Подключения сотрудников к рабочей сети"
  },
  "outbound:my-server": {
    "title": "Мой сервер",
    "description": "Выход через выбранный сервер"
  }
}
```

Ключ — `inbound:` или `outbound:` плюс фактический тег из вашего конфига.
Можно задать только `title` или только `description`; остальные сведения останутся
автоматическими. Файл перечитывается при опросе страницы, перезапуск не нужен.
Без этого файла все пояснения определяются автоматически. Страны, адреса серверов
и личные названия не зашиты в программу. Локальные подписи сохраняются при обновлении
бинарника и не отправляются на GitHub. Файл рекомендуется хранить с правами `0600`.
При ошибке JSON статистика продолжает работать с автоматическими пояснениями
и показывает сообщение об ошибке подписей. Размер файла ограничен 64 КиБ,
заголовок — 160 символами, описание — 800 символами.

## Обновление со страницы

После входа раздел «Обновление программы» показывает установленную версию.
Проверка стабильных [GitHub Releases](https://github.com/lobacom/xkeen-stats/releases)
выполняется при открытии страницы и затем не чаще одного раза в 6 часов;
кнопка «Проверить обновления» позволяет проверить вручную (не чаще раза в минуту).
Установка начинается только по кнопке «Обновить до …».

Сервис выбирает сборку для своей архитектуры, проверяет подпись Ed25519 списка
контрольных сумм и SHA256 исполняемого файла. Открытый ключ встроен в программу;
произвольные URL, неподписанные сборки, предварительные релизы и понижение версии
через API не поддерживаются. Для загрузки используется HTTPS с проверкой сертификата,
в том числе CA-bundle Entware. Токен GitHub на роутере не требуется.

Перед установкой проверяются версия нового бинарника и совместимость с текущими
конфигурацией, авторизацией и историей. Рабочий бинарник сохраняется в закрытой папке
`/opt/var/lib/xkeen-stats/update/job-*/previous`. Установка заменяет только бинарник
и кратко перезапускает сервис статистики. Пароль, сессии, история, init-скрипт,
LAN-hook и конфигурация Xray не заменяются. Сам Xray не перезапускается.

Если новая версия не проходит проверку запуска и получения статистики, отдельный
процесс обновления восстанавливает предыдущий бинарник и запускает его. Обновлённый
init-скрипт также проверяет прерванную установку перед запуском после перезагрузки.
Журнал и состояние находятся в закрытой папке `update`; резервная копия бинарника
сохраняется для ручного восстановления. Совместимые форматы auth/state должны
сохраняться в выпусках с автоматическим обновлением.

Первая установка поддержки обновлений требует ручного обновления бинарника и
init-скрипта. После этого очередные версии устанавливаются со страницы.
Доступны сборки Linux amd64, arm64, armv7, mips и mipsle (MIPS softfloat).
Для другой архитектуры установка выполняется вручную.

### Выпуск новой версии

Сопровождающий изменяет `VERSION`, проверяет код и отправляет соответствующий тег
`vX.Y.Z`. Workflow `.github/workflows/release.yml` запускает тесты, собирает бинарники
и публикует Release с `SHA256SUMS` и `SHA256SUMS.sig`. Ключ подписи хранится в GitHub
Actions secret `RELEASE_SIGNING_KEY` и локально вне репозитория; его значение никогда
не должно попадать в Git, журнал workflow или аргументы команд. Инструмент
`cmd/release-sign` читает ключ только из окружения и проверяет соответствие встроенному
открытому ключу. Утрата ключа потребует отдельного перехода доверия; автоматически
генерировать новый ключ для каждого релиза нельзя.
Для повторного выпуска существующего тега workflow также можно запустить вручную,
указав тег в поле `tag`. Сборка использует исходники этого тега.
